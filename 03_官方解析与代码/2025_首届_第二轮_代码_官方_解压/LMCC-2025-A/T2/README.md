# T2 数学作业解答助手

## 故事背景

你来到小学帮助小朋友学习数学。孩子们每天都会来问你各种数学填空题，但他们希望能看到类似题目的解法作为参考。

好在，学校数学老师整理了一个包含**100道数学题**的题库，每道题都包含题目、答案和详细解析。你决定开发一个**基于检索增强生成（RAG）**的数学助手：
1. 使用 **Embedding 模型**从题库中检索最相似的题目
2. 参考这些相似题目的解法来解答当前问题
3. 输出包含解题思路和最终答案的标准JSON格式

这样，即使是小模型，也能通过学习相似题目的解法来准确解答数学题！

**什么是 RAG？**  
RAG（Retrieval-Augmented Generation）= 检索 + 生成：
```
问题 → 用Embedding检索相似题目 → 将相似题目作为参考 → 模型基于参考生成答案
```

**优势**：
- 通过相似题目提供解题思路
- 基于实际例子学习，更容易理解
- 可以不断扩充题库，无需重新训练模型

## 任务目标

你需要在 `submission.py` 中完成**五个核心函数**：

### 1. ⭐ 相似度计算函数：`compute_similarity(query_embedding, doc_embedding) -> float`（20分）

**这是单独评测的函数！** 实现余弦相似度计算。

**输入**：
- `query_embedding`: 查询的 embedding 向量（torch.Tensor）
- `doc_embedding`: 文档的 embedding 向量（torch.Tensor）

**输出**：
- `float`: 余弦相似度，范围 [-1, 1]，值越大表示越相似

**余弦相似度公式**：
```
cos(θ) = (A · B) / (||A|| * ||B||)
```
其中：
- A · B 表示向量点积
- ||A|| 表示向量A的L2范数（模长）
- ||B|| 表示向量B的L2范数（模长）

**评测方式**：
- 使用 20 个查询，每个查询在题库中有对应的最相似题目
- 检查你的函数能否正确找到最相似的题目
- 每题1分，共20分

### 2. 检索函数：`retrieve_relevant_problems(query, problem_bank, embedding_model, tokenizer, top_k, get_embedding_func) -> List[Dict]`

使用 embedding 模型从题库中检索最相似的题目。

**输入**：
- `query`: 查询文本（用户的问题）
- `problem_bank`: 题库列表，每个元素包含 id, problem, answer, explanation 字段
- `embedding_model`: 预加载的 Qwen3-Embedding-0.6B 模型
- `tokenizer`: embedding 模型的 tokenizer
- `top_k`: 返回最相关的前 k 个题目
- `get_embedding_func`: 获取文本 embedding 的函数（评测系统提供）

**输出**：
- 包含最相关的 `top_k` 个题目的列表

**实现要求**：
1. 使用 `get_embedding_func` 获取 query 和题目的 embedding
2. 使用 `compute_similarity()` 函数计算相似度
3. 按相似度降序排序，返回 top_k 个


### 3. 用户消息组装：`build_user_message(problem, retrieved_problems) -> str`

组装用户消息（包含检索到的相似题目和当前题目）。

**输入**：
- `problem`: 当前要解答的题目
- `retrieved_problems`: 检索到的相似题目列表，每个元素包含 id, problem, answer, explanation 字段

**输出**：
- 完整的用户消息字符串

**实现要求**：
- 决定如何格式化和组织检索内容与当前题目

### 4. System Prompt 定义：`build_system_prompt() -> str`

编写 system prompt，引导模型参考相似题目来解答问题。

**要求**：
1. 引导模型理解数学填空题的任务
2. 说明会提供检索到的相似题目作为参考
3. 要求模型以 JSON 格式输出，包含 reasoning 和 answer 两个字段
4. answer 字段只包含数字，不包含单位

### 5. 配置生成参数：`build_generation_parameters() -> dict`

配置模型生成时的参数。

**可配置参数**：
- `max_new_tokens`: 最大生成 token 数
- `do_sample`: 是否使用采样
- `temperature`: 温度参数
- `top_p`: nucleus sampling 参数
- `enable_thinking`: 是否开启 Thinking 模式

### 示例说明

**示例：RAG 问答流程**

**输入题目**：
```
一个数除以5商是12余3，这个数是多少？
```

**期望输出**：
```json
{
  "reasoning": "根据除法关系，被除数 = 除数 × 商 + 余数。这个数 = 5 × 12 + 3 = 60 + 3 = 63",
  "answer": "63"
}
```

**RAG 流程说明**：
1. 使用 Embedding 模型检索题库中最相似的 3 道题
2. 可能检索到：除法余数问题、除法关系问题等
3. 参考这些题目的解法和解析
4. 生成包含解题思路和最终答案的 JSON

**难点说明**：
- 需要正确实现余弦相似度计算
- 需要从题库中检索到真正相关的题目
- 需要合理组织检索内容，引导模型学习解题方法
- 需要控制模型输出标准 JSON 格式
- 答案必须只包含数字，不包含单位

**输出内容**（Demo 模式）：
- **第一部分**：
  - 查询文本
  - 期望找到的题目ID
  - 实际找到的题目ID
  - 最高相似度
  - 判定结果（✅/❌）
- **第二部分**：
  - 题目内容
  - 检索到的相似题目（ID、题目、答案）
  - 用户消息（部分）
  - 模型输出的 JSON
  - 正确答案
  - 提取的答案
  - 判定结果（✅/❌）
  - 单题耗时
